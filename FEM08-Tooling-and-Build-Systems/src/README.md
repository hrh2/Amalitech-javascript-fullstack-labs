# Developer Dashboard

A lightweight, card-catalog–themed dashboard of developer resources (docs, videos, guides)
for the **Tooling & Build Systems** module. Built to practice npm, Vite, ESLint, and Prettier
as a cohesive front-end workflow — not to demo application complexity.

## Stack

- **Package manager:** npm
- **Bundler / dev server:** Vite (vanilla JS template)
- **Linting:** ESLint 8 (`.eslintrc.json`, classic config)
- **Formatting:** Prettier (`.prettierrc`) + `eslint-config-prettier` to avoid rule conflicts

## Getting started

```bash
npm install       # install dependencies
npm run dev       # start Vite dev server (http://localhost:5173)
npm run build     # production build -> dist/
npm run preview   # serve the production build locally
npm run lint       # run ESLint against src/
npm run format      # run Prettier --write across the project
```

## Feature overview

- Resources (8 total) are modeled as plain objects with `name`, `category`
  (`package` / `build` / `quality`), `type` (`docs` / `video`), `desc`, and `link`.
- The grid re-renders from a single `state = { query, category }` object — typing
  in the search box or clicking a category tab both call the same `render()` function.
- Each card gets a generated "call number" (e.g. `PKG.001`) from its category, echoing
  a library card-catalog drawer, which is this project's visual signature element.

## Accessibility fixes applied

An audit flagged four issues; all four are fixed in this build:

- **Contrast** — `--wood`, `--wood-dark`, `--tab-gold`, and the search placeholder
  color were darkened. Every text/background pair in the design now meets WCAG AA
  (4.5:1) — verified with a contrast-ratio script against the final palette.
- **Heading order** — added an `<h2>Cards on file</h2>` before the `<h3>` card
  titles, so headings run `h1 → h2 → h3` with no skipped level.
- **Main landmark** — the app root in `index.html` is now `<main id="app">` instead
  of a plain `<div>`.
- **Identical links** — each "check out resource" link now carries a unique
  `aria-label="Check out <resource name>"`, so links with the same visible text
  have distinct accessible names.

## Reflection: how Vite's build process helps

During development, Vite serves source files over native ES modules and only
transforms the file you're actually looking at, so the dev server starts almost
instantly and updates on save feel immediate — no waiting for a full bundle to
recompute. For production, `vite build` switches to a bundled, minified output:
it merges modules, strips unused code, hashes filenames for cache-busting, and
inlines small assets, which keeps the shipped payload small and lets browsers
cache it aggressively between deploys. The result is a workflow where iteration
is fast locally and the final artifact is still lean, without hand-tuning a
bundler configuration.
